# Отладка Л4

Отладочная операция — отметка задачи `t1` в списке `inbox`. События и изменения кеша сняты с Redux middleware на реальном json-server с задержкой 1500 мс. Прогон с отказом использует `CHAOS_RATE=1` для воспроизводимого ответа 500. Порядок действий можно сравнить с вкладками Action и Diff в Redux DevTools.

## Успешная отметка

| Действие Redux | Наблюдение |
|---|---|
| `history/pendingChanged` | Запись заблокирована для повторного ввода |
| `api/executeMutation/pending` | Начат PATCH для `updateTask` |
| `api/queries/queryResultPatched` | `getTasks("inbox")`: `done` изменился с false на true до ответа |
| `api/queries/queryResultPatched` | Вложенные задачи в `getLists` изменились, счётчик уменьшился |
| `api/executeMutation/fulfilled` | PATCH подтверждён, теги запускают фоновое чтение |
| `history/recorded` | Команда записана, стеки изменились с [0, 0] на [1, 0] |
| `history/pendingChanged` | Запись разблокирована после чтения |

## Отметка с ответом 500

| Действие Redux | Наблюдение |
|---|---|
| `history/pendingChanged`, `api/executeMutation/pending` | Запись начата, кнопки истории заблокированы |
| `api/queries/queryResultPatched` × 2 | `done` изменился с true на false в двух кешах |
| `api/executeMutation/rejected` | Сервер вернул 500 |
| `api/queries/queryResultPatched` × 2 | Обратные патчи вернули true и прежний счётчик |
| `api/invalidateTags`, `ui/notify` | Запрошено согласование, показано уведомление |
| `history/pendingChanged` | Стеки остались [0, 0], запись снова доступна |

После патчей в журнале также идут служебные действия `api/invalidation/updateProvidedBy`. Их payload обновляет сведения о тегах. Для воспроизведения журнала в PowerShell запустите `$env:TODO_DEBUG_TRACE = '1'; npm test`.

## Diff при отмене

В сценарии редактирования стек `past` содержал две команды, `future` был пуст. В начале отмены `api/queries/queryResultPatched` изменил `done` с true на false и восстановил прежние значения названия, описания и времени. После успешного PATCH действие `history/undone` переместило команду из `past[1]` в `future[0]`. В опыте с ответом 500 обратный запрос был откатан, верхняя команда осталась в `past`.

В Redux DevTools переход к предыдущему снимку меняет отображаемое Redux-состояние. Кнопка отмены отправляет реальный обратный запрос, поэтому результат виден после перезагрузки.

## Перерисовки при отметке

В первоначальной реализации замер в Edge с React Strict Mode выполнен счётчиками вызовов компонентов во временно инструментированных Vite-модулях. За один цикл отметки и согласования кеша функция `TaskItem` вызвалась 8 раз, `ListContent` — 8, `SubmitButton` — 4, `ListHeader` и `AddTaskForm` — по 0. Подписка кнопки сохранения на блокировку вынесена в дочерний компонент. Свойства заголовка при отметке стабильны, а форма получает стабильный обработчик. Эти числа отражают вызовы в Strict Mode, а не количество commit-событий.

В React Developer Tools этот сценарий воспроизводится записью Profiler с включённым объяснением перерисовок. В Redux DevTools выбираются действия из таблиц и проверяются вкладки Action, Diff и RTK Query. Снимки экранов расширений в автоматизированном прогоне не снимались.
